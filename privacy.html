Privacy policy

Last updated: 10 November 2026 · Applies to One Off Desktop and the One Off YouTube channel.

The short version: One Off Desktop is a personal tool with a single user — the owner of the One Off YouTube channel. It does not collect anything about anyone else, because nobody else can use it. It stores one Google OAuth refresh token on the owner's own computer and sends video files to the owner's own YouTube channel. Nothing is sold, shared or sent anywhere else.

1. Who this policy is about

One Off is a personal YouTube channel that publishes videos about software development. One Off Desktop is a small command-line application that the channel's owner runs on their own machine to upload finished videos.

There is no sign-up, no user accounts, no mailing list, and no way for a member of the public to use the application. If you are a viewer of the YouTube channel, this policy is relevant to you only in the sense that Google's own privacy policy applies to YouTube.

2. What Google user data is accessed

The application requests exactly two OAuth scopes:

ScopeWhat it allowsWhy it is needed
youtube.upload Upload a video file to the authorising account's own channel. This is the entire purpose of the tool: putting a finished episode on the channel.
youtube.force-ssl Manage the authorising account's own channel resources, including setting a video thumbnail. The channel uses custom thumbnails, which must be uploaded alongside the video.

The application does not request access to Gmail, Google Drive, Contacts, Calendar, Analytics, Search Console or any other Google service. It does not read watch history, subscriptions, comments or private viewer data. It cannot read any other YouTube channel.

3. How that data is used

  • To upload a local video file to the One Off channel with a title, description and tags.
  • To attach the matching thumbnail image to that video.
  • Nothing else. No analytics, no profiling, no automated decision-making about people.

4. What is stored, and where

ItemWhere it livesRetention
OAuth client credentials and refresh token A local folder on the owner's own computer (~/.oneoff/). Never transmitted to any server other than Google's token endpoint. Until the owner deletes the file or revokes access.
Video files and thumbnails The owner's computer and the owner's Google Drive, then YouTube. As long as the video stays published.
Local metadata (titles, tags, upload status) A local SQLite file on the owner's computer. Until the owner deletes it.

No data is stored on any server operated by One Off, because no such server exists. No data is stored in cookies or local storage on this website, and this site runs no analytics or tracking scripts of any kind.

5. Sharing

Google user data is not sold, rented, traded or transferred to any third party. It is not used for advertising, and it is not used to train machine learning models. The only recipient of the data is Google itself, because that is where the video is being uploaded. One Off's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

6. Your control over the data

Access can be revoked at any time at myaccount.google.com/permissions. Revoking it immediately invalidates the stored refresh token; the application will simply stop working until it is authorised again. Deleting ~/.oneoff/ removes every credential the application holds.

Because the application has only one user, and that user is the owner of the channel, requests about stored data can only come from that owner. If you believe otherwise, write to the address below.

7. Security

Credentials are stored in files readable only by the owner's operating-system account, outside any code repository, and are excluded from version control. The application communicates with Google exclusively over HTTPS. No credential is ever written to this website, to a log that leaves the machine, or to a third party.

8. Children

The channel and the application are not directed at children under 13, and the application has no mechanism by which a child could use it.

9. Changes

Material changes to this policy will be published on this page with a new "last updated" date. Because there is a single user, changes are also communicated to that user directly.
